Procedural simulation of a **forest ecosystem** in C++ on Unreal Engine 5.7. Trees are born, compete for light, water and nutrients, age and die, and are rendered at the same time with geometry generated in real time.

## Features

- **Procedural terrain:** fractal noise with *domain warping* and ridges, plus hydraulic and thermal erosion.
- **Resource fields:** water (topographic wetness index), nutrients and light (3D grid with Beer-Lambert extinction under the canopies).
- **Large-scale population:** thousands of trees in parallel arrays (SoA) with logistic growth, stress, mortality, seed dispersal and germination.
- **Trees generated by space colonization (SCA)**, with phototropism and self-pruning.
- **Three-level-of-detail rendering:** *hero trees* with their own mesh, instances (ISM) and *impostors*, plus a ground layer (stumps and leaf litter).
- **Configurable species** as data assets. Includes two biomes: the **Garajonay** laurel forest and the **Sierra de la Demanda** temperate forest.
- **Reproducible:** deterministic random number generator, with an independent stream per subsystem.
- **Console-driven:** 42 commands and 17 CVars (`Eco.*`), heat maps over the terrain and 31 automation tests.

## Requirements

| Component | Requirement |
|---|---|
| Operating system | Windows 10 22H2 / 11 (64-bit) |
| Engine | **Unreal Engine 5.7** (exact version) |
| Compiler | Visual Studio 2022 17.14 or later, with the components listed in [`.vsconfig`](.vsconfig) |
| Version control | Git 2.40+ and **Git LFS 3.x** |
| GPU | DirectX 12 with Shader Model 6. Hardware ray tracing recommended (RTX 2000+ / RX 6000+) and 8 GB of VRAM |
| RAM | 16 GB minimum, 32 GB recommended |
| Disk | ~100 GB free on an SSD |

> [!IMPORTANT]
> **Git LFS is mandatory.** All `.uasset` and `.umap` files are stored in LFS. Without it, the clone downloads ~130-byte pointers instead of the real assets, the project opens empty and the forest never grows.

If your GPU does not support hardware ray tracing, disable it (see the [usage guide](Guia_de_Uso.pdf), §2.4).

## Installation

```bash
git lfs install                  # once per machine
git clone https://github.com/Izana-L/ProceduralEcosystem.git
cd ProceduralEcosystem
git lfs pull                     # force-download the assets
```

1. Right-click `ProceduralEcosystem.uproject` → **Generate Visual Studio project files**.
2. Open `ProceduralEcosystem.sln` in Visual Studio 2022, select **Development Editor / Win64** and build (`Ctrl+Shift+B`). The first build takes between 5 and 20 minutes.
3. Launch the editor with `F5` or by double-clicking the `.uproject`. It starts directly in the `TestingMap` level.

The first time, the editor compiles shaders for 20–60 minutes. This is normal and happens only once per machine.

> [!TIP]
> Clone the repository close to the drive root (for example `C:\Dev\ProceduralEcosystem`) to avoid long-path errors. Do not delete `Directory.Build.targets`: it is a required patch.

## Quick start

Press **Play** (`Alt+P`), open the *Output Log* and the console with the `` ` `` key, and type:

```
Eco.SeedForest 300     # sow 300 seedlings across the terrain
Eco.Demografia         # how many there are of each species
Eco.Step 50            # advance 50 simulated years
Eco.TogglePause        # let time run
Eco.PaintVigor         # vigor heat map over the terrain
Eco.GrowHeroTree 0     # detailed tree of species 0
Eco.LOD.Stats          # distribution of trees by level of detail
```

- The simulation starts **paused**.
- Almost every command requires Play mode. Outside of it they do nothing and show no error.
- Responses are written to the *Output Log*. Filter by `Eco` to remove engine noise.
- The terrain used by the simulation is an in-memory array, **invisible** until it is exported to a Landscape. See the procedure in the usage guide, §8.

The full command library, the terrain generation workflow and how to configure a new species are covered in the [usage guide](Guia_de_Uso.pdf).

## Tests

The 31 automation tests are not console commands. Run them from the `Cmd` box of the *Output Log* (no need to be in Play), or from *Tools → Session Frontend → Automation*:

```
Automation RunTests Eco
```

Or from the command line, headless:

```bat
UnrealEditor-Cmd.exe "C:\Dev\ProceduralEcosystem\ProceduralEcosystem.uproject" ^
    -ExecCmds="Automation RunTests Eco; Quit" -unattended -nullrhi -nosplash
```

## Project structure

```
ProceduralEcosystem/
├── Source/ProceduralEcosystem/     # C++ code (a single Runtime module)
│   ├── Public/ and Private/
│   │   ├── Core/                   # Deterministic RNG, grids, utilities
│   │   ├── Config/  Species/       # Project settings and species traits
│   │   ├── Terrain/                # Terrain, erosion, water, nutrient and light fields
│   │   ├── Ecology/                # Biological model and population
│   │   ├── Simulation/             # Tick orchestrator and console commands
│   │   ├── Geometry/               # Procedural trees (SCA), mesh, foliage, wind
│   │   ├── Render/                 # LOD, instances, impostors, ground layer
│   │   ├── Debug/                  # Heat maps, profiler, audit
│   │   └── Test/                   # Automation tests
├── Config/                         # DefaultGame.ini (calibration) and DefaultEngine.ini
├── Content/
│   ├── Species/                    # Species assets (Garajonay, SierraDemanda)
│   ├── My_Levels/                  # TestingMap, the startup level
│   ├── Materials*/  Textures/      # Custom materials and textures
│   └── Fab/  MSPresets/            # Third-party resources (Megascans)
├── Guia_de_Uso.pdf
└── Documentación técnica.pdf
```

The simulation calibration (more than 130 parameters) is edited from **Edit → Project Settings → Game → Procedural Ecosystem** and saved to `Config/DefaultGame.ini`.
